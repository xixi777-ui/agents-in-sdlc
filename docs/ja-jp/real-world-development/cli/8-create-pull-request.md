フィルタリングの実装、命令の更新、スキルの更新、品質保証 (QA) プロファイル、テストが、1 つのブランチに保存されています。まとめてレビューし、プルリクエストを作成しましょう。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にマージの手順を任せます。

> [!NOTE]
> 通常は、機能、命令の更新、スキルの更新、QA エージェントをいくつかの PR に分けます。このワークショップでは、手順を簡潔にするため、フィルタリングと品質に関する一連の作業を 1 つの会話とブランチにまとめ、この PR に含めています。

このレッスンでは、次のことを学びます。

- Agent Merge とは何か、マージのライフサイクルをどのように自動化するかを理解します。
- 機能の変更全体と検証結果を確認します。
- フィルタリングの PR を作成します。
- レビュー後にのみ Agent Merge を有効にし、PR がマージされたことを確認します。

## シナリオ

フィルタリングのワークフロー全体を通じて、Copilot を使って機能を計画、実装、検証してきました。Tailspin Toys は、開発者がマージを許可する権限を維持したまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、プルリクエストを取り込むために必要な残りの作業を自動化します。有効にすると、Copilot は PR を妨げている要因に対応します。たとえば、失敗した継続的インテグレーション (CI) チェックの修正、レビューコメントへの対応、必要に応じたリベースを行い、リポジトリで許可されていれば GitHub の自動マージを有効にします。

これまでは、自分で **プルリクエストをマージ**を選択していました。Agent Merge にその役割を任せられます。有効にする前に作業をレビューし、マージできる状態か判断してください。

## Agent Merge で PR を管理する

すべてのコードを作成したら、まとめてレビューして PR を作成し、残りの手順を Agent Merge に任せましょう。

1. Codespace に戻ります。
2. `/agent` と入力してエージェント ダイアログを開きます。
3. 選択肢から **Default** を選び、<kbd>Enter</kbd> を押します。
4. `/pr create` コマンドを使って新しい PR を作成します。
5. `/pr agentmerge` を使って Agent Merge を有効にします。
6. Copilot が PR の継続的インテグレーション処理を監視します。すべて成功すると、マージが実行されます。
7. Copilot から「PR #14 was squash-merged successfully.」のようなメッセージが表示されたことを確認します。

> [!IMPORTANT]
> Agent Merge は、必須の承認、ブランチ保護、マージキュー、リポジトリ設定、権限不足を回避しません。ブロックされた場合は、報告された理由を確認し、リポジトリで許可されている場合はレビュー済みの変更を手動でマージしてください。

## まとめと次のステップ

コードの生成、テストと検証に加えて、プルリクエストの手順も含む開発プロセスの複数の部分を自動化しました。次のことを行いました。

- Agent Merge とは何か、マージのライフサイクルをどのように自動化するかを学びました。
- 機能の変更全体と検証結果を確認しました。
- フィルタリングの PR を作成しました。
- レビュー後に Agent Merge を有効にし、PR がマージされたことを確認しました。
