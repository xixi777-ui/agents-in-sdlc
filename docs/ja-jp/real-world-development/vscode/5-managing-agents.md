GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。この作業は自分のマシン上でリアルタイムに実行されるため、VS Code の Copilot Chat では、すべてのツール呼び出しやファイル編集の進捗を確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトを送って会話を案内できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示し、高コントラスト モードに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントは、高コントラスト モードを実装しています。作業中に、デザイン チームから追加の依頼がありました。デフォルトのテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始めるのではなく、既存のセッションを案内して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作ボタンとともに、チャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツールの操作を確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** 表示を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの実行に許可が必要な場合 (たとえば、ターミナル コマンドの実行)、エージェントは一時停止し、**Allow** の確認を表示します。問題ないコマンドだけを許可してください。

5. エージェントが高コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライトモードの追加を依頼する

高コントラスト モードを実装できたので、同じ会話でライトモードの切り替えを追加します。チャット セッションを続けることで、エージェントは前の作業のコンテキストを保持します。変更したコンポーネント、使ったスタイルの方針、設定したローカル ストレージのパターンなどが含まれます。

1. Copilot Chat の入力欄に、次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは、すでに行った変更を確認し、ライトモードの追加を提案します。
3. 高コントラスト モードのときと同じように、新しい編集を確認しながら **Keep** または **Undo** を選択します。
4. 望ましくない方向に進んだ場合 (たとえば、好みと異なる方法でトグル UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 進行中のセッションを案内すると、最初からやり直すよりも速く調整できます。追加のプロンプトで変更を依頼できます。「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使う」、「3 つ目のトグルは追加せず、ライトモードを既存の設定パネルに組み込む」のように方向を修正したり、「両方の切り替えにキーボード ショートカットも追加する」のように範囲を広げたりできます。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティのパターン (ARIA 属性、キーボード ナビゲーション、セマンティック HTML、ローカル ストレージへの保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して案内しました。ファイル編集を確認しながら採用または取り消し、コンテキストを保ったまま追加のプロンプトで作業を広げました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- 追加のプロンプトで進行中のセッションを案内する。

[次のレッスン][next-lesson]では、アクセシビリティ関連の作業をプルリクエストとして公開し、この演習を通じてローカルのカスタムエージェントが作成した変更をレビューします。
